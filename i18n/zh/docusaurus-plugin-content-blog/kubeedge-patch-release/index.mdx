近日，KubeEdge Security Team 对外公布了多项安全公告，同步推出 **v1.23.1、v1.22.2、v1.21.2** 三个安全补丁版本，本次更新重点修复边缘节点任务执行、配置更新、安装包解压和通信协议处理等多个路径安全隐患。

本次补丁更新覆盖当前维护中的多个 release 分支。建议正在使用受影响版本的用户尽快升级到对应补丁版本，规避潜在安全风险。

| 补丁版本 | 适用分支 | 说明 |
| :---: | :---: | :---: |
| v1.23.1 | release-1.23 | 安全补丁版本 |
| v1.22.2 | release-1.22 | 安全补丁版本 |
| v1.21.2 | release-1.21 | 安全补丁版本 |

## 本次修复的问题

本次安全补丁主要针对 **4 类** 高频安全风险完成优化修复。以下为面向终端用户的通俗说明，开发者可前往 KubeEdge GitHub 安全公告页查阅完整细节。

| CVE | 影响组件 | 问题类型 | 影响概述 |
| :---: | :---: | ----- | ----- |
| CVE-2026-62371 | NodeUpgradeJob | 命令执行路径加固 | 影响边缘节点升级任务执行路径 |
| CVE-2026-62182 | ConfigUpdateJob | 命令执行路径加固 | 影响边缘节点配置更新任务执行路径 |
| CVE-2026-62369 | keadm | 解压路径校验加固 | 影响 Windows 边缘节点安装 / 加入流程 |
| CVE-2026-62370 | viaduct packer | payload 长度校验加固 | 影响 CloudHub 资源稳定性 |

本次修复没有引入新的用户侧功能，主要目标是对安全敏感路径进行输入校验、命令执行方式调整和资源边界限制。

## 问题详细分析

### CVE-2026-62371 ｜ NodeUpgradeJob 命令执行路径加固

📌 **漏洞成因**

KubeEdge v1alpha2 版本升级 API 中，NodeUpgradeJob 处理器直接拼接用户可控的 *spec.version*、*spec.image* 字段内容，拼接为 shell 命令执行。攻击者可通过传入特殊 shell 元字符，构造恶意升级参数，实现任意系统命令注入执行。

💡 **风险**

拥有 NodeUpgradeJob 资源创建/更新权限的认证用户，可远程控制目标边缘节点，以升级进程权限执行任意命令，完全接管边缘节点，影响节点机密性、完整性、可用性。

📘 **受影响版本**

* 1.12.0 ≤ 版本 < 1.21.2
* 1.22.0 ≤ 版本 < 1.22.2
* 1.23.0 ≤ 版本 < 1.23.1

⚙️ **修复方案**

NodeUpgradeJob 用于管理边缘节点升级任务。此次修复对升级任务中的命令构造和参数传递方式进行了加固，避免将外部输入拼接到 shell 命令中执行。

补丁中将相关执行路径调整为更安全的参数化调用方式，并增加了对应测试，降低边缘节点升级任务中的命令注入风险。

🗒️ **安全版本**：1.21.2、1.22.2、1.23.1

🔍 **对应公告**：*GHSA-5jpj-293f-rhvj*

### CVE-2026-62182 ｜ ConfigUpdateJob 命令执行路径加固

📌 **漏洞成因**

KubeEdge 配置更新任务 ConfigUpdateJob 处理逻辑存在命令注入缺陷，程序直接将用户可控的 *updateFields* 字段拼接至系统命令并通过 shell 执行。未对特殊字符做过滤转义，恶意配置字段可触发任意命令执行。

💡 **风险**

具备 ConfigUpdateJob 资源操作权限的攻击者，可下发恶意配置更新任务，在目标边缘节点执行任意系统指令，窃取业务数据、篡改服务配置、植入持久化后门，全面控制边缘业务节点。

📘 **受影响版本**

* 1.21.0 ≤ 版本 < 1.21.2
* 1.22.0 ≤ 版本 < 1.22.2
* 1.23.0 ≤ 版本 < 1.23.1

⚙️ **修复方案**

ConfigUpdateJob 用于边缘侧配置更新。此次修复针对 *updateFields* 等配置更新字段进行了命令执行路径加固，避免配置值被作为 shell 片段解释执行。

补丁对参数处理方式进行了调整，并补充了配置更新相关测试，提升配置更新任务的安全性。

🗒️ **安全版本**：1.21.2、1.22.2、1.23.1

🔍 **对应公告**：*GHSA-m3c6-2p7h-cfr3*

---

### CVE-2026-62369 ｜ keadm 解压路径校验加固

📌 **漏洞成因**

KubeEdge 工具 keadm 的 *DecompressTarGz* 解压函数存在路径遍历漏洞，解压压缩包时未严格校验文件路径，未过滤 `../` 父目录穿越、Windows 反斜杠、绝对路径、盘符路径等危险字符，导致可跨目录写入文件。

💡 **风险**

该漏洞主要影响 Windows 边缘节点，攻击者可构造恶意 *tar.gz* 安装包，在节点接入、安装升级过程中，覆盖系统配置、可执行文件、服务文件，实现系统持久化篡改，最终触发代码执行风险。

📘 **受影响版本**

* 1.16.0 ≤ 版本 < 1.21.2
* 1.22.0 ≤ 版本 < 1.22.2
* 1.23.0 ≤ 版本 < 1.23.1

⚙️ **修复方案**

keadm 是 KubeEdge 中用于安装、初始化和加入边缘节点的重要工具。本次修复增强了 *DecompressTarGz* 解压逻辑的路径校验能力，避免归档文件中的异常路径写入到目标目录之外。

该问题尤其与 Windows 边缘节点安装或 join 流程相关。补丁中增加了路径归一化、绝对路径检查、父目录穿越检查以及安全路径拼接，确保解压目标始终位于预期目录内。

🗒️ **安全版本**：1.21.2、1.22.2、1.23.1

🔍 **对应公告**：*GHSA-9vm9-pqxx-x83v*

---

### CVE-2026-62370 ｜ viaduct packer payload 长度校验加固

📌 **漏洞成因**

KubeEdge CloudHub 依靠 *viaduct* 打包器解析边缘节点上报报文，程序直接读取报文头部 32 位载荷长度值，未设置内存分配上限校验，直接按照读取到的数值申请内存缓冲区，存在无限制内存分配缺陷（CWE-789）。

💡 **风险**

已完成认证的恶意/失陷边缘节点可构造超大载荷长度的恶意报文持续发送，触发 CloudHub 内存疯狂占用，引发内存耗尽、进程 OOM 崩溃、服务反复重启，进而造成云边通信暂时中断，影响边缘集群业务可用性；该漏洞仅能实现拒绝服务，无法窃取数据或执行代码。

📘 **受影响版本**

* 1.0.0 ≤ 版本 < 1.21.2
* 1.22.0 ≤ 版本 < 1.22.2
* 1.23.0 ≤ 版本 < 1.23.1

⚙️ **修复方案**

本次针对超大载荷长度导致的过度内存分配问题进行了针对性优化修复，为 *viaduct* 通信报文设置了 32MiB 的最大载荷上限。同时在报文收发、读写全流程加入长度校验规则，在系统分配内存之前提前识别并拦截超大异常报文，有效避免恶意请求触发内存超限占用问题。此外，团队补充了正常报文、超限恶意报文等多场景测试用例，覆盖各类异常情况，多方位修复该漏洞。

🗒️ **安全版本**：1.21.2、1.22.2、1.23.1

🔍 **对应公告**：*GHSA-gfw4-49f9-cp25*

## 用户应该怎么做

如果你正在使用 KubeEdge v1.21.x、v1.22.x 或 v1.23.x，建议尽快升级到对应补丁版本。

| 当前版本 | 建议升级版本 |
| ----- | :---- |
| v1.23.x | v1.23.1 |
| v1.22.x | v1.22.2 |
| v1.21.x | v1.21.2 |

升级前建议完成以下检查：

* 备份现有配置和关键数据
* 阅读对应版本 release notes
* 在测试环境中验证升级流程
* 升级 CloudCore、EdgeCore、keadm 等相关组件
* 检查边缘节点升级、配置更新、节点 join 等流程是否正常

## 社区安全响应过程

本次安全修复由 KubeEdge Security Team 协调推进，整体流程包括漏洞确认、影响范围分析、修复方案设计、master 分支修复、release 分支回溯、补丁版本发布以及 GHSA / CVE 信息公开。

在修复过程中，社区全面梳理了各类安全敏感执行链路，并为不同 release 分支补充必要测试和 CI 修复，确保补丁能够稳定回溯到当前维护版本。

云边协同架构下，边缘节点通常分散部署在多网络、多运行环境中，安全补丁的及时迭代与升级落地，是保障集群安全稳定运行的关键。后续 KubeEdge 社区将持续优化安全响应机制，不断提升云边协同基础设施的安全性与运行可靠性。
