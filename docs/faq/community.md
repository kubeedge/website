## How do I get started contributing to KubeEdge?

Start with the [contributing guide](../community/contribute.md). It explains how to set up a development environment and find work, including beginner-friendly issues. You can also review the [build guide](../developer/build.md) before making a code change.

When you open a pull request, describe the change clearly and follow the repository's contribution instructions. Documentation fixes are also welcome.

## Where can I get help?

Use the KubeEdge [Slack workspace](https://kubeedge.slack.com) for community discussion and the [GitHub issue tracker](https://github.com/kubeedge/kubeedge/issues) for bug reports and feature requests. Include your KubeEdge version, the steps you took, what you expected, and relevant logs. Avoid posting credentials, tokens, or private data in public issues.

For questions that do not need a bug report, check whether [GitHub Discussions](https://github.com/kubeedge/kubeedge/discussions) is enabled for the repository.

## How often does KubeEdge release?

KubeEdge's [release guide](../community/release.md) describes an approximately three-month release cycle and a typical monthly patch cadence. Check the [releases page](https://github.com/kubeedge/kubeedge/releases) for current versions and dates.

## Where can I find community meetings and groups?

The [community repository](https://github.com/kubeedge/community) is the current source for community group information and meeting schedules. The website's [governance page](../community/governance.md) explains the SIG and Working Group structure.

## What are the KubeEdge community roles?

The project documents the roles of Member, Approver, Maintainer, and Owner in its [membership guide](../community/membership.md). Read that page for current requirements and responsibilities; this FAQ does not add separate thresholds.

## Where can I find case studies and production users?

See the KubeEdge [adopters list](https://github.com/kubeedge/kubeedge/blob/master/ADOPTERS.md) and the website's [case studies guide](../community/casestudies.md).

## How do I report a security vulnerability?

Do not report a suspected vulnerability in a public issue. Follow the [KubeEdge security policy](https://github.com/kubeedge/community/blob/master/team-security/SECURITY.md), which gives the private reporting address and explains how the team handles reports. Keep vulnerability details confidential while the team investigates.

## Is there a code of conduct?

KubeEdge follows the [CNCF Code of Conduct](https://github.com/cncf/foundation/blob/main/code-of-conduct.md). If you experience or witness unacceptable behavior in the project, follow the reporting options in that policy.
